# Registro de riscos

| # | Risco | Probabilidade | Impacto | Resposta |
|---|---|---|---|---|
| R1 | Equipe com pouca experiência em desenvolvimento web atrasa as entregas | Alta | Alto | **Mitigar:** priorizar os itens Must, fazer protótipos simples primeiro e reservar tempo de estudo |
| R2 | Escopo cresce com novas ideias (ranking, dashboard, feedback privado) e o prazo estoura | Média | Alto | **Evitar:** congelar o escopo Must; novas ideias vão para o backlog Should/Could |
| R3 | Falha ou instabilidade do sistema durante o evento | Baixa | Alto | **Mitigar:** testes antes do evento (Semana 19), backup dos dados e plano manual de contingência |
| R4 | Jurados com dificuldade para lançar notas | Média | Médio | **Mitigar:** interface simples, teste de usabilidade e instruções rápidas |
| R5 | Link de submissão inválido ou repositório privado | Média | Médio | **Mitigar:** validar o formato do link e orientar as equipes sobre repositório público |
| R6 | Indisponibilidade de um integrante da dupla (doença, provas, outras entregas) | Média | Médio | **Aceitar/Mitigar:** manter o código e a documentação no GitHub para que os dois possam continuar o trabalho um do outro |
